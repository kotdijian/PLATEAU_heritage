# Changelog

## 0.4.0

- Primary geospatial outputs changed to GML + GeoPackage; GeoJSON is no longer generated by the standard pipeline.
- Every per-municipality output filename now receives the 5-digit municipality-code prefix (for example `13106_heritage.gpkg`).
- Renamed the analytical Building layer to `heritage_buildings_footprint` to make clear that it is a 2D derivative of the original CityGML Building.
- Added spatial layer `heritage_building_complexes`: one MultiPolygon feature per matched Heritage Complex, preserving every member Building footprint as a separate polygon part.
- Complex geometry is never buffered, convex-hulled, dissolved, or expanded across inter-building space.
- Added relational table and CSV `heritage_complex_members` linking each Complex to its exact PLATEAU Building members.
- Unmatched Complexes do not receive inferred polygon geometry; they remain in `heritage_complex_summary` and point/unresolved outputs.
- Companion Heritage JSON/XML prototype updated to version 0.4 and now records Building Complex membership.
- Movable-only Building associations now also retain their Complex IDs/names in selected Building metadata.

## 0.3.1

- Retry PLATEAU GML downloads with exponential backoff.
- Remove stale partial downloads.
- Record download failures separately from cultural-property non-matches.
- Continue prefecture batch after a municipality download failure.
- Add --resume to skip completed municipalities and retry failed ones.

## 0.3.0

- Processing model changed to `building_direct / point / movable`.
- All non-movable cultural geometries are normalized to representative points; no cultural buffer/area matching.
- Ordinary `point` records match Buildings only by exact point-in-footprint.
- Unmatched records are emitted to the point layer; all source points remain in `heritage_records`.
- Movable properties are grouped by same normalized cultural address.
- Fixed address normalization bug where `1-2` could become `12`.
